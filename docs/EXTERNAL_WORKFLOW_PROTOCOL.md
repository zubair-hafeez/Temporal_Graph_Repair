# Independent workflow sources: protocol before outcome access

The literature refresh identified an existing six-scenario synthetic relational/OCEL collection by Alessandro Berti, released 24 August 2026, DOI https://doi.org/10.5281/zenodo.22079246. This is important prior art: producing multitype simulated operational logs, provenance and reference OCELs is already available. Our paper cannot claim the first such generator or dataset factory.

Use the collection as independent simulator evidence for the repair task, subject to verified license metadata. The alphabetical first two scenarios, BatteryVault and ClaimStream, are additional development domains. ForgeFlow, PermitFlow, ProcureChange and TrialVersion are reserved for later confirmation after the method and adapters are frozen. This split is declared before downloading record contents or measuring any repair outcome. The six logs are simulations from one published collection, not six independently collected real-world datasets. Their relational source databases and alternative serializations must not be counted as additional independent samples.

Download only the JSON OCEL representation and integrity/metadata files initially. Source row provenance, source-record identifiers and redundant identity attributes must be excluded from learner features. The original event-object reference supports controlled faults; uncorrupted object-object links cannot silently expose relations being repaired. Preserve native event fields separately from any denormalized observation track. Use declared primary and secondary entity types from the dataset documentation rather than choosing types by measured method performance.

BPI 2017 and BPI 2019 final targets remain sealed. BPI 2012 check also remains reserved. Expanding development does not authorize relabeling inspected outcomes as final tests.

Related simulation prior work also includes Knopp, Pourbafrani and van der Aalst, *Discovering Object-Centric Process Simulation Models*, ICPM 2023, https://ieeexplore.ieee.org/document/10271944/. The current paper must earn its contribution through the repair task, reusable observation/task boundary and validated learning/application outcomes, not simulation alone.

## First development slice, fixed before repair outcomes

For each of the two development logs, use the half-open timestamp window from the 25th to the 50th event-time percentile. Include all records at the lower boundary and exclude all at the upper boundary; source row order cannot split simultaneous events. This bounds the initial CPU experiment without selecting successful or complete entity histories. Metrics concern the available window, with possible left/right censoring, rather than complete lifetime reconstruction. Retain the typed catalog of objects referenced in this window and all event-object links before fault application.

Repair the documented primary/secondary types: BatteryPack and ServiceOrder for BatteryVault; Claim and Exposure for ClaimStream. Other types provide observed context. Actor is converted to an anonymized resource handle. The native event-attribute allowlist is amount, quantity, currency, unit, actor_role, resource_calendar, location, is_exception, exception_reason, reason and changed_field. Drop raw object identifiers appearing in these values; do not retain source_system, source_table, source_record_id, recorded_at, old_value, new_value, object attributes, object-object links or relationship qualifiers. These choices are shared across the two logs, not tuned to outcomes. In particular, no primary/secondary relationship qualifier is exposed to the policy.

Prepare clean, original mixed-fault and independent pipeline-fault observations at seed 61001. Start with the existing v2 synthetic-only boosted policy and its generated-validation thresholds, four decoding rounds, 128 participation candidates and 64 identity candidates. Record clean preservation as well as damaged-history restoration. These are development experiments; subsequent changes must retain these initial outcomes.
