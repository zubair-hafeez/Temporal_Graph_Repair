# Task contract — development version 1

## Objective and evidence boundary

Restore event-object participation and fragmented object identities in an offline observation window. Unusual execution is preserved; observation damage is repaired. Prediction code receives only the observed graph and a declared schema. Reference values, source case grouping, corruption provenance, and evaluator queries are separate artifacts.

The three planned fault families are missing participation, incorrect participation, and namespace fragmentation. Timestamp coarsening is a condition, not an exact-time recovery target. The main task does not reveal which events are corrupted. A known-hole diagnostic reveals an event and missing object type; it must always be labeled as an easier track.

Existing object catalogs are assumed available. A catalog identifies possible entities, not their missing event participation. Source identifiers are replaced with shuffled opaque handles and are never numerical predictors. A separate open-catalog setting may later evaluate objects lacking a trusted registry. Do not silently mix these settings.

## Data boundary

- Logistics OCEL: public simulated development data, already explored. All observed object-object relations may form an additional explicit-evidence baseline, but must be included equally for all methods in that track and corrupted consistently when redundant with damaged facts.
- BPI 2012: real-source development. Its source trace containers become evaluator-only case memberships. Learners see event activity/lifecycle, time, and observed case/resource participation. Exclude case-level amounts and raw IDs from the first structural comparison to avoid repeated case fingerprints.
- BPI 2017 and BPI 2019: final real-source targets remain sealed for model selection. Existing audited prefixes and related core objects will be excluded by a recorded split manifest before evaluation. Schema-only inspection is allowed and must be recorded.
- Source facts provide controlled-corruption reference labels, not independently certified truth about naturally occurring faults.

Normalize event order by occurrence time and a seed-based random tie breaker, never original trace order. Participant IDs and event handles are anonymized independently. Event activity and lifecycle are available categorical observations, not hidden labels. Global sorting does not establish a strict order between simultaneous events.

## First bounded experiment

Before a neural implementation, evaluate known-hole restoration on logistics and BPI 2012 under independent and contiguous missing links. Report:

1. All eligible hidden links, including ones with no surviving co-participant.
2. Candidate recall at fixed budgets and fraction with no observable history.
3. Uniform and degree priors, unnormalized and normalized co-occurrence, temporal proximity, activity-aware matching, and a combined matching model selected on development data only.
4. Ties using fractional correctness or explicit abstention, never source ordering.
5. Clean/faulted graph counts, actual severity, source/code hashes, runtime, and seed.

The diagnostic may use a known missing type. It cannot establish deployment diagnosis, alias recovery, model novelty, or publication readiness. Follow it with mixed clean/corrupt events and fragmentation before choosing the final learning task. Saturation is a reason to simplify the method, not to hide strong baselines.

## Split and access discipline

Hash core BPI 2012 case IDs into development-fit, development-tune, and development-check groups before anonymization. Keep source-to-group mappings in evaluator metadata only. Shared resources may appear across groups; process each partition separately so no held-out event enters another partition's context. Logistics is exploratory development, not an independent frozen test.

For generated worlds, group all observations and counterfactual variants of an execution together. Hold out mechanism compositions, not only seeds. Freeze final-test settings and code before opening target outcomes. If target results motivate a revision, retain and disclose the earlier run and use a fresh reserved confirmation partition.

## Progress gates

Proceed to generation/model development only after verifying that some evidence supports recovery and strong cheap baselines leave an application-relevant gap. Continue toward a positive application paper only if improvements survive matched inputs, held-out mechanisms, real-source transfer, and preservation of correct facts and genuine exceptions. There is no guaranteed acceptance outcome.

Factory integration is a later bounded unit within this paper: common record/observation/task interfaces, workflow module, repair task, and a prefix-only prediction reuse check. No complete factory implementation is required.
