# Confirmation design — not frozen, no reserved outcomes opened

This is a working design. Freeze a concrete version with source/model/config hashes after development selects a useful method. Do not call an exploratory result confirmatory after inspecting it. The goal is a publishable application study, not merely completion of the code or benchmark.

## Practical claim to test

Executable temporal worlds can supply useful training supervision for restoring entity histories when verified operational histories are unavailable or scarce. The study must show which observation and recording conditions support transfer, retain genuine exception records and expose failures. No new neural architecture, universal repair guarantee, universal factory, or first synthetic-data platform is claimed.

## Reserved evidence

- BPI2012 check: same-process confirmation only; not an unseen process.
- BPI2017 and BPI2019: real-source controlled-fault confirmation, with native-field and structural views explicitly separated. Previously inspected source prefixes and objects must be handled through the existing audit manifest. No redundant identity-valued attributes or clean O2O evidence may expose the answer.
- ForgeFlow, PermitFlow, ProcureChange and TrialVersion: four unopened scenarios from the independent public simulation collection. Treat them as scenarios from one simulator collection, not four independent real deployments.
- Reserved factory mechanism compositions: generated extrapolation, not substitutes for independent sources.

Adapters, event-window selection, target types and legitimate field lists must be fixed from public schema/recording contracts before repair outcomes. Selection cannot use model success, completeness of reference histories or fault masks. Histories are scored within the declared available window; censoring is explicit.

## Comparisons and information parity

Keep no repair, strong temporal/context matching, a source-trained matching pipeline, the strongest generated edit learner, compatible neural controls, fixed sequencing and one pass. A documented physical-rule baseline receives only constraints actually available in its track. Published native-task reproductions and adaptations have separate labels. Never supply correct trace containers to a baseline when membership is the prediction target.

Separate synthetic-only, extra-corruption self-supervision, self-supervision plus generated training, and verified-history training. Compare generated calibration separately from source-verified or pseudo-label calibration. All source labels used for fitting, validation, rule choice or operating-point selection count in a final total-annotation claim. Existing 16/64/256 development experiments do not meet that total-cost contract.

The principal generation ablations must control executed worlds, available queries, fault recipes and learning capacity. The v5 paired observation comparison already preserves exact executions/faults; its changed candidate pools must be reported. Additional volume or simulator-diversity studies need explicit matched budgets.

## Repetition and outcomes

Use at least three independent generated-training collections for the principal method and paired fault seeds on each target. Changing a deterministic boosted learner's random_state alone is not a meaningful training-data replicate. Repeat verified-history selection where label efficiency is claimed. Report each process/type and the clean counterparts, rather than hiding a failed domain in a pooled average.

Primary outcomes are per-entity history precision/recall/F1 and exact-history recovery. Accompany them with false-merge counts, identity recall, candidate coverage, initially correct event preservation, genuine exception-evidence retrieval and runtime. Model-selected thresholds have no out-of-domain precision guarantee. Quantify variation across actual runs without treating individual events as independent experimental replicates.

The independent pipeline-fault family remains a development stressor currently unseen during training. If it enters training in a later iteration, withdraw any unseen-mechanism claim for it and declare a genuinely reserved recording mechanism before final evaluation.

## Readiness decision

A convincing result needs useful history and application-query improvements on independent processes, a strong no-clean-label comparison, and acceptable clean-record preservation at an operating point chosen without target outcomes. General gains cannot be claimed if the method works only after manually choosing a favorable observation view for each target. Preserve negative results, identify unobservable cases and compare complexity with the simpler control. The manuscript must state measured boundaries even if they restrict the claim.

Once the final protocol is frozen, run all declared comparisons and retain every target outcome. Do not use the reserved results to repeatedly tune the same method while calling those results final tests. The final review package requires a complete manuscript, figures, references, commands, artifacts, data permissions and a claim-by-claim evidence audit. Submission remains the user's decision.
